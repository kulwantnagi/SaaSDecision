# Tool Categorization & Open-Source Alternative Mapping Rules

1. **NEVER rely solely on high-level categories (e.g. `Productivity & Notes`)** when assigning open-source alternatives or commercial alternatives to software tools.
2. **ALWAYS assign functional semantic `tags`** to every new tool (e.g. `project-management`, `voice-dictation`, `ai-meeting-notes`, `e-signature`, `link-in-bio`, `testimonials`, `uptime-monitoring`, `crm`, `screen-capture`, `social-media`).
3. **Match Open-Source Alternatives using precise sub-functionality and keywords** from the tool's description/name rather than defaulting to broad fallback tools like AppFlowy or Logseq:
   - `project-management` -> OpenProject, Plane, Taiga
   - `voice-dictation` -> Handy, OpenWhispr, Buzz
   - `ai-meeting-notes` -> Anarlog, Meetily, Quill Meetings
   - `e-signature` -> Documenso, Anvil
   - `link-in-bio` -> LittleLink, BioDrop
   - `testimonials` -> OpenTestimonial, Formbricks
   - `video-recording` -> Cap, OBS Studio
   - `ai-customer-service` -> Chatwoot, Botpress
